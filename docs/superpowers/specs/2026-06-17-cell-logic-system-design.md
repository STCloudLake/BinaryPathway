## 1. 格点基本单元

每个 1×1 单位格点（Grid 格点或逻辑块上的格点）是一个独立的"寄存器"，具有以下状态：

### 1.1 状态定义

| 状态 | 表示 | 含义 |
|------|------|------|
| 纯值 | `value: v` (v ∈ {0, 1}) | 该格点仅持有一个布尔值 |
| 值+逻辑 | `v L ___` | 该格点持有值 v 和逻辑运算 L，等待一个真值输入 |
| 仅逻辑 | `L ___` | 该格点仅有逻辑运算 L，没有值（等待被捕获或直接赋真值） |

其中 L ∈ {AND, NAND, OR, NOR, XOR, XNOR}。NOT 不在方块系统中参与（由 SprayBottle 提供）。

### 1.2 状态转换规则

```
纯值 v ──(接受逻辑 L)──→ v L ___  (等待真值)
v L ___ ──(接受真值 v₂)──→ 计算 r = v L v₂ → 纯值 r
纯值 v ──(SprayBottle)──→ 纯值 (1-v)
v L ___ ──(SprayBottle)──→ (1-v) L ___  (仅翻转值部分)
L ___   ──(SprayBottle)──→ L' ___       (逻辑翻转: AND↔NAND, OR↔NOR, XOR↔XNOR)
纯值 v ──(接受真值 v₂)──→ 非法 — 禁止操作（必须先有逻辑运算）
```

## 2. 方块兼容性与连接规则

### 2.1 兼容性判断

两个 1×1 格点单元在物理接触（面插座连接）时的行为：

| 格点 A | 格点 B | 行为 |
|--------|--------|------|
| `纯值 v₁` | `纯值 v₂` | **吸附连接** — 纯物理连接，不计算 |
| `纯值 v` | `v₂ L ___` | **合并计算** — `v₂ L v = r`，A 和 B 所在格点的状态均解析为 `纯值 r`（逻辑被消耗） |
| `v₁ L₁ ___` | `v₂ L₂ ___` | **吸附连接** — 两者都在等待，互不满足，纯物理连接 |
| `纯值 v` | `L ___`（仅逻辑，无值） | **捕获** — 逻辑块获得值 v，变为 `v L ___` |

### 2.2 多单位方块组合

方块可以具有 1×N 的多个单位格点。每个格点独立携带其状态。

**组合规则**：
- 两个多单位方块通过某个面的格点接触时，按 §2.1 逐格点判断兼容性
- 兼容的格点对执行计算
- 不兼容的格点对仅物理吸附
- 组合后方块整体成为一个更大的聚合体（可以是不规则形状：直线、L形/手枪形等）

## 3. 连接案例

### 案例 1：直线组合 1×2 + 1×2 → 1×3

```
方块 A (1×2): [1] [1 AND ___]
方块 B (1×2): [1] [1]

B 从右侧连接 A（B 的左格点接触 A 的右格点）:

连接前:  [1] [1 AND ___] ←→ [1] [1]
                ↑ 接触面        ↑
                A右格点      B左格点

格点对: A[1 AND ___] + B[1] → 1 AND 1 = 1
A右格点解析为 [1]
B左格点被消耗/合并

连接后:  [1] [1] [1]   (1×3 直线)
```

### 案例 2：手枪形组合

```
方块 A (1×2): [1] [1 AND ___]
方块 B (1×2): [1] [1]

B 从下方连接 A 的右格点（B 的上格点接触 A 的右格点下表面）:

俯视:    [1] [1 AND ___]
              │ (向下连接)
              [1]
              [1]

格点对: A右格点[1 AND ___] + B上格点[1] → 1 AND 1 = 1
A右格点解析为 [1]

结果:   [1] [1]
            [1]    (L 形/手枪形)
```

### 案例 3：两个待计算块相接 — 端对端 (1×2 + 1×2 → 1×3)

```
方块 A (1×2): [1] [1 AND ___]
方块 B (1×2): [1] [1 AND ___]

B 旋转 180° 后从右侧连接，使 B 的 [1] 格点接触 A 的 [1 AND ___]:

连接前:  [1] [1 AND ___] ←→ [1] [1 AND ___]  (B已旋转)
                ↑ 接触面

格点对: A右格点[1 AND ___] + B左格点[1] → 1 AND 1 = 1

连接后:  [1] [1] [1 AND ___]   (1×3, 尾端仍有一个待计算的 AND)
```

### 案例 4：两个待计算块相接 — 对调 (1×2 + 1×2 不相容)

```
方块 A (1×2): [1] [1 AND ___]
方块 B (1×2): [1] [1 AND ___]

B 旋转 180° 后"对调"连接:

连接:   A的 [1 AND ___] 接触 B(旋转后)的 [1 AND ___]
        → 两者都在等待真值 → 不兼容 → 仅物理吸附

结果:   [1] [1 AND ___ | 1 AND ___] [1]
        两个等待中的格点物理相连，各自保持独立状态
        整体为 1×4，中间两个格点均为等待状态
```

### 案例 5：仅值块长链连接

```
方块 C (2×1): [1] [1]
方块 D (2×1): [1] [1]

C 的任意面连接 D 的任意面:
    所有格点都是纯值 → 全部仅为物理吸附
    结果: [1] [1] [1] [1] (1×4 或 2×2 取决于连接方向)
```

## 4. 逻辑块 + 真值块的放置流程

### 4.1 场景空间组装

1. 玩家从场景中拾取逻辑块（预制体，具有 1×N 格点配置，所有格点的初始逻辑为同一类型 L）
2. 玩家将真值块（Tile_1 或 Tile_0）连接到逻辑块的某个特定格点面
3. 该格点状态更新（纯值 + 逻辑等待，或如果已有等待则计算）
4. 重复直到玩家满意
5. 玩家将组装完成的聚合体抓起，放置到 Grid 上

### 4.2 放置到 Grid — 约束与规则

**硬约束**（违反则拒绝整个放置操作）：

1. **边界约束**：聚合体必须完全在 Grid 范围内。任何格点超出 Grid 边界 → 拒绝放置。
2. **冲突约束**：聚合体覆盖的每个格点，如果对应 Grid 位置上已有物理方块（PuzzleInitializer 放置的 Tile_0/Tile_1），则拒绝整个放置。

**放置计算**（约束通过后，对聚合体的每个格点 cell 独立执行）：

```
对聚合体的每个格点 cell:
    grid_cell = Grid[cell.position]

    if cell 是 "v L ___":
        if grid_cell 有值 grid_v:
            计算: r = v L grid_v
            grid_cell 的值更新为 r
        else:
            grid_cell 状态变为 "v L ___" (逻辑块覆盖了空格点)

    elif cell 是 "纯值 v":
        if grid_cell 有值 grid_v:
            两者纯值 → 仅物理吸附，各自保持
        else:
            grid_cell 的值设为 v

    elif cell 是 "L ___" (仅逻辑):
        if grid_cell 有值 grid_v:
            grid_cell 变为 "grid_v L ___" (Grid 值被捕获)
        else:
            grid_cell 变为 "L ___" (等待值)
```

### 4.3 BFS 处理 "L ___" 状态的空 Grid 格点

当逻辑块放置到空 Grid 格点且仅有逻辑没有值（`L ___`），或放置后产生 `v L ___` 等待状态时：

- **BFS 将此格点视为断路（等价于 0）**。只有逻辑的节点显然不连通。
- 玩家必须提供真值完成计算，使格点变为纯值 1，路径才能连通。

## 5. SprayBottle (NOT 喷雾 / 逻辑翻转)

- NOT 是单目运算，不参与方块合并/连接系统
- 喷雾瓶是场景中的独立道具
- 喷洒目标：任何格点（Grid 上的、逻辑块上的、场景中方块上的）
- 限制：每关可使用次数有限（LevelData.sprayUses）

### 5.1 喷洒效果表

| 目标状态 | 喷洒效果 |
|----------|----------|
| `纯值 v` | `纯值 (1-v)` |
| `v L ___` | `(1-v) L ___`（仅翻转值部分，逻辑不变） |
| `L ___`（仅逻辑，无值） | `L' ___`（逻辑翻转） |

### 5.2 逻辑翻转对照表

| 原逻辑 | 翻转后 |
|--------|--------|
| AND | NAND |
| NAND | AND |
| OR | NOR |
| NOR | OR |
| XOR | XNOR |
| XNOR | XOR |

## 6. 与 BFS 连通性检测的关系

BFS 连通性检测仅关心 Grid 上每个格点的**最终真值**：

- `纯值 1` → 参与连通路径
- `纯值 0` → 不参与（断路）
- `v L ___`（等待中）→ **视为断路**，不参与路径
- `L ___`（仅逻辑）→ **视为断路**，不参与路径

谜题设计意义：处于等待状态的格点不能成为路径的一部分。玩家必须先完成逻辑计算使格点变为纯值 1，路径才能连通。这创造了"必须先用逻辑块组合再用真值解锁"的谜题机制。

## 8. 术语表

| 术语 | 定义 |
|------|------|
| 格点 (Cell) | 1×1 单位的逻辑寄存器，Grid 或逻辑块上的最小单元 |
| 纯值 (Pure Value) | 格点状态：仅持有 0 或 1，无逻辑运算 |
| 值+逻辑 (Value+Logic) | 格点状态：持有值 v 和逻辑运算 L，等待第二个真值 |
| 仅逻辑 (Logic Only) | 格点状态：仅有逻辑运算 L，无值 |
| 吸附连接 (Snap Connect) | 两个兼容格点的物理连接，通过面插座 Joint 实现 |
| 合并计算 (Merge Compute) | 值+逻辑格点接受真值 → 执行 v L v₂ → 解析为纯值 |
| 聚合体 (Aggregate) | 多个方块通过面插座组合形成的多单位整体 |
| 逻辑块 (Logic Block) | 携带逻辑运算（AND/OR/XOR 等）的多单位方块 |
| 真值块 (Value Tile) | 携带纯值 0 或 1 的方块（Tile_0 / Tile_1） |
| 捕获 (Capture) | 仅逻辑格点接触纯值格点时，获得该值变为 `v L ___` |
